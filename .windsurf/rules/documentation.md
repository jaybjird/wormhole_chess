# Documentation Rules

## Pre-Coding Task Rules

- Always read `/docs` directory before starting any coding task
- Check for existing documentation that provides project context
- Look for setup guides, architecture decisions, and API specifications
- Review any TODO items or documented requirements
- Use the GitHub MCP to pull down the Milestones and open Issues tagged with Story for additional context

## Code Review Documentation Rules

- During code reviews, check `/docs` directory for any documentation updates needed
- Verify that code changes align with documented architecture
- Ensure new features are documented appropriately
- Check if any API changes require documentation updates

## Documentation Structure

- `/docs/setup.md` - Development setup and project structure
- Additional docs should be added as the project grows
- Keep documentation in sync with code changes
- Use markdown format for all documentation

## Documentation Review Checklist

- [ ] Have I read relevant docs before coding?
- [ ] Does this code change require documentation updates?
- [ ] Are API changes documented?
- [ ] Is setup guide still accurate?

## Git Workflow Rules

- [ ] I will not push commits to origin without user review
- [ ] All code changes require user approval before being pushed to remote repositories
- [ ] Commits should be locally staged but not pushed until explicitly reviewed and approved
